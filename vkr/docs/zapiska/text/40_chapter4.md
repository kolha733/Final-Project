## 4.2 Э1. Валидация генератора

Вопрос эксперимента: совпадают ли параметры дрейфа в порождённых данных с заданными (величина, форма перехода, доля класса, шум) и воспроизводим ли поток по seed. Фактическая величина оценивается по данным, независимо от истинной разметки (подраздел 3.4), вместе со стандартной ошибкой SE. Генератор считается корректным, если нормированные отклонения $z = (\hat m - m)/\mathrm{SE}$ распределены примерно как стандартный нормальный закон.

Заданная и фактическая величина на сетке. Рассматривается одно внезапное событие в середине потока ($d = 10$, $\pi_0 = 0{,}3$, $\alpha = 0{,}5$, без шума) для каждой пары «вид, величина» с несколькими seed реализации (рисунок @fig:e1calib). На сетке из {{ e1.grid_runs }} прогонов все $\left| z \right| \le 3$ (максимум {{ e1.grid_max_z }}), стандартное отклонение $z$ равно {{ e1.grid_sd_z }}, средняя оценка отличается от заданной величины не более чем на {{ e1.grid_bias }}. Строки сетки с одним seed не независимы: при одном seed базовые случайные величины совпадают для всех $m$, поэтому независимую проверку даёт следующий опыт.

![Заданная и фактическая величина дрейфа на сетке (среднее и интервал по seed реализации)](docs/figures/zapiska/fig_5_1_e1_calibration.png){#fig:e1calib width=12}

Случайные сценарии. Берутся {{ e1.rand_n }} случайных сценариев со случайными видом, величиной, долей класса $\pi_0 \in [0{,}05;\ 0{,}5]$, долей затронутых признаков и размерностью $d \in [3;\ 40]$. Объём выбран так, чтобы отличить стандартное отклонение 1 от заметно меньшего значения: выборочное стандартное отклонение по $n$ значениям имеет относительную погрешность около $1/\sqrt{2n}$, то есть при наименьшем числе сценариев одного вида ({{ e1.rand_per_kind }}) — около {{ e1.rand_rel_err }}. В пробных прогонах на 100 и 300 сценариях стандартное отклонение $z$ для виртуального дрейфа составило 0,76 и 0,84, что ещё совместимо с 1 с учётом поправки на множественность, но уверенного вывода не давало; поэтому объём был увеличен. Для каждого вида строится доверительный интервал для стандартного отклонения по распределению $\chi^2$ с поправкой Бонферрони на три вида (таблица @tbl:e1random).

Форма перехода. Для реального дрейфа величины 0,3 с шириной перехода 6000 сравниваются четыре варианта: внезапный, постепенный с линейной и с сигмоидной функцией, инкрементальный (рисунок @fig:e1shape). Эмпирическая кривая — скользящая (окно 800) доля объектов, у которых метка расходится с правилом старого концепта. Сравнивать её нужно с теоретической кривой, сглаженной тем же окном: иначе ступенька внезапного дрейфа даёт формальное расхождение {{ e1.shape_raw_sudden }}, вызванное только сглаживанием. Для всех четырёх форм отклонение эмпирической кривой от сглаженной теоретической лежит в пределах от {{ e1.shape_min }} до {{ e1.shape_max }}. При $m = 0{,}3$ кривая инкрементального поворота почти линейна, поэтому по доле смены метки инкрементальный переход почти неотличим от постепенного линейного; формы различаются механизмом (при постепенном дрейфе объект порождён старым или новым концептом, при инкрементальном — промежуточным).

![Эмпирическая, теоретическая и сглаженная теоретическая кривые перехода реального дрейфа](docs/figures/zapiska/fig_5_3_e1_transitions.png){#fig:e1shape}

Дисбаланс, шум и воспроизводимость. Доля класса воспроизводится с отклонением не более {{ e1.prior_dev_se }} SE. Доля инверсий меток равна {{ e1.flip_1 }} при $\eta = 0{,}1$ и {{ e1.flip_2 }} при $\eta = 0{,}2$; она одинакова при разных $\pi_0$, потому что шум берётся из отдельного подпотока генератора псевдослучайных чисел. Для всех трёх групп семейств выполнены пять свойств воспроизводимости: одинаковый seed даёт побитово одинаковый поток, другой seed — другой поток, истинная разметка не зависит от seed реализации, сохранение сценария в YAML и загрузка дают тот же поток, изменение шума не меняет признаки.

Классические потоки на единой шкале. Для классических генераторов river вычислены TV смены соседних вариантов функции и побочное изменение доли класса (таблица @tbl:e1classic).

«Смена функции» — внутренний параметр с неконтролируемой величиной от {{ e1.classic_min }} до {{ e1.classic_max }}, несопоставимый между генераторами: из {{ e1.classic_n }} смен лишь {{ e1.classic_small }} имеют TV < 0,25. У SEA TV совпадает с $\left| \Delta P(y) \right|$: все изменённые метки меняются в одну сторону, поэтому каждая смена концепта SEA одновременно является сдвигом доли класса той же величины. Это количественно подтверждает первый пробел (подраздел 1.5): область малых и средних величин чистого реального дрейфа ручные бенчмарки почти не покрывают.

Реальные данные. Величина внедрённого дрейфа воспроизводится точно на эмпирической мере: для виртуального и априорного дрейфа — до округления, для реального — с точностью до массы одной строки (наибольшее отклонение {{ e1.real_err }}). Побочное изменение $P(y)$ у событий реального дрейфа достигает {{ e1.real_dpy }}, предупреждение W4 выдано для {{ e1.real_w4 }} из {{ e1.real_n }} таких событий; у событий виртуального дрейфа побочное изменение не превышает {{ e1.virtual_dpy }}. Порождение $10^5$ объектов занимает доли секунды, поэтому генерация не является узким местом экспериментов.

На смешанном наборе связь F1 с величиной слабее, чем на сетке: $\rho$ от {{ e3.e2_rho_m_min }} до {{ e3.e2_rho_m_max }}, значимо после поправки — у {{ e3.e2_rho_m_sig }}. Проверка механизма показала, что шум сильно связан с частотой ложных тревог этих детекторов ($\rho$ не ниже {{ e3.eta_far_min }}), но слабо — с превышением recall над случайным уровнем ($\left| \rho \right| \le$ {{ e3.eta_excess_max }}). ## 4.11 Обсуждение и угрозы валидности

Результаты экспериментов согласуются с формальной моделью. Единая шкала величины оказалась содержательной: величина в TV — главный фактор сложности обнаружения, а доля затронутых признаков при фиксированной TV на качество не влияет. Виртуальный дрейф по потоку ошибок на синтетике не обнаруживается, что следует из утверждения 6. Автоматически сформированный набор дал выводы о детекторах, отличные от выводов на ручном наборе: качество ниже, порядок другой, а лучший по F1 метод — периодический сброс, не анализирующий данные. Эти результаты показывают, почему бенчмарк должен равномерно покрывать пространство сценариев и сопровождаться базовыми линиями.

Угрозы валидности:

- объём: в режиме {{ run.mode }} набор Э2 содержит {{ e2.scenarios }} сценариев (число повторов — {{ e2.repeats }}), поэтому мощность части проверок (анализ по одному фактору, правила отказа, MTD) невелика; {{ run.full_note }}
- модель и параметры: базовая модель одна (гауссовский наивный байесовский классификатор), параметры детекторов — значения river по умолчанию; выводы относятся к этой конфигурации;
- семейство: синтетическое семейство линейно-гауссовское; перенос на реальные данные частичный, согласие ранжирований не подтверждено (Э7);
- протокол: окно допуска 2000 совпадает с периодом базовой линии Periodic, и при широких переходах окна покрывают большую часть потока (Э4); поэтому вместе с recall приводится его превышение над случайным уровнем, рассчитанным в пуассоновском приближении;
- множественные сравнения: поправка Холма применяется внутри каждого семейства проверок, но не ко всем проверкам главы одновременно.
